用 Cloudflare 搭建自己的节点管理面板-forkedgetunnel

发表于2026-11-15|更新于2026-11-15|Tutorials
|总字数:2.1k|阅读时长:6分钟

之前写过一篇 edgetunnel 的部署教程。后来我基于这个项目做了自己的修改，加入了管理面板、在线优选、本地测速入口和 Windows 部署工具，整理成了 forkedgetunnel。这篇文章介绍目前版本的功能和部署方法。

项目地址：https://github.com/Chengeeker/forkedgetunnel

上游项目：https://github.com/cmliu/edgetunnel

本文按当前项目 README 整理，Cloudflare 界面可能更新，遇到菜单位置变化时以控制台和项目文档为准。

💡 这个项目有什么功能

  • Worker、登录页和管理面板放在同一个仓库中部署。
  • 支持 VLESS、Trojan、Shadowsocks 节点和订阅生成，可配置 ProxyIP 和链式代理。
  • 支持在线导入 IP、域名和网段，进行 HTTPS 初筛、批量测速和结果导入。
  • Windows 可安装 CFData-WEB 本地优选工具，也可以通过本地 mihomo 控制接口测试节点延迟。
  • 可选的 VPN Gate 链式订阅默认关闭，适用于支持相应配置的 mihomo / Clash Meta 客户端。

网络表现会受到运营商、客户端、Cloudflare 和外部服务的影响，优选结果也会随时间变化。

⚙️ 部署前准备

准备好 Cloudflare 账号和 GitHub 账号，再将 forkedgetunnel Fork 到自己的 GitHub。需要自定义域名的话，还要准备一个自己能管理 DNS 的域名。

下面介绍 Pages 连接 GitHub 的方式。Windows 用户也可以直接看后面的“一键部署”。两种方式的 KV 配置不同，按各自步骤填写即可。

🛠 Pages + GitHub 部署

1. 获取账号 ID 和 KV Token

  1. 打开 Cloudflare 控制台，选择目标账号，在 Workers & Pages → 账号详情 中复制 Account ID。不要复制域名的 Zone ID。
  2. 在 API 令牌页面创建令牌，选择目标账号，添加 Workers KV Storage → Edit（Workers KV 存储 → 编辑） 权限。
  3. 创建后复制令牌完整值，后面要作为加密变量保存。令牌和管理员密码不要上传到 GitHub，也不要发给别人。

新版界面的具体点击位置可参考 README 的 Token 教程。Token 需要属于 Pages 所在账号，并有该账号的 KV 权限。

2. 创建 Pages 项目

  1. 在 Workers & Pages 中创建 Pages 项目，选择连接 Git，授权并选择自己 Fork 的仓库。
  2. 生产分支选 main，框架选 None，根目录使用仓库根目录。使用 V2 或更新的构建系统和 Node.js 20 及以上版本。
  3. 构建设置填写：
项目 填写内容
构建命令 node scripts/prepare-pages.cjs
构建输出目录 dist
  1. 在首次保存和部署之前，为生产环境添加下面四个变量：
变量名 填写内容 类型
ADMIN 自己设置的后台密码 建议加密
CLOUDFLARE_ACCOUNT_ID 前面复制的账号 ID 普通文本
CLOUDFLARE_API_TOKEN 前面创建的 KV Token 完整值 加密 / Secret
KV_NAMESPACE_NAME 固定的存储名称，例如 forkedgetunnel-myproject-production-KV 普通文本

存储名称由自己填写，首次不需要提前创建。以后更新项目或更换域名时继续使用同一个名称。如果已经有需要保留的 KV 数据，用 KV_NAMESPACE_ID 填原命名空间 ID，替代 KV_NAMESPACE_NAME。 两者同时填写时 ID 优先。

  1. 检查完成后点击保存并部署，等待构建成功。程序会在首次通过鉴权读取后台配置时创建或复用 KV。已有原生 KV 绑定时优先使用原绑定。
  2. 需要自定义域名时，在 Pages 项目的 自定义域 中添加，例如 proxy.example.com，按控制台提示配置 DNS，并等待证书生效。
  3. 打开 https://你的部署域名/admin，输入 ADMIN 密码。修改一项设置并保存，重新打开页面，确认配置仍然存在。

如果已有项目以前只填了 ADMIN，补齐上述账号 ID、Token 和存储名称或 ID 后，还需要触发一次新部署。不要把普通文本变量命名为 KV 来代替原生绑定。详细步骤见已有项目补救说明。

🪟 Windows 一键部署

  1. 下载 Pages-Deploy-Windows.zip，完整解压后双击 redeploy-pages.cmd。
  2. 输入 1 创建新项目，输入 2 再次部署已有项目。项目名填写 Cloudflare 控制台中的名称，不带网址。
  3. 首次使用按提示填写账号 ID 和部署 Token。初次创建需要 Cloudflare Pages 编辑和 Workers KV Storage 编辑权限，并按提示填写 GitHub 仓库、分支和后台密码。GitHub 仓库需要提前在 Cloudflare 完成授权。
  4. 初次部署会创建或复用 KV 并添加原生绑定。再次部署时脚本备份配置、保留原 KV，解除自定义域名关联后删除并重建项目，再恢复域名。检查屏幕显示的目标后，在最后一步直接回车确认。

再次部署期间服务会中断，旧部署历史和部署挂钩不会保留，域名证书可能需要等待。不要提前手动删除原项目或 KV。已有加密变量无法从 Cloudflare 读回，需要提供原值或使用本机已保存的备份。

脚本说明、权限和中断恢复方法见 Windows 部署教程。

🔑 首次使用和订阅

进入 /admin 后检查协议、传输方式和订阅设置，再通过“获取节点链接”复制适合客户端的订阅。保存设置后，还要在客户端更新订阅。

需要使用自己整理的地址时，将优选订阅模式切换为 自定义订阅（支持汇聚订阅），检查“自定义优选地址”并保存。随机优选模式不会按这份自定义列表下发节点。客户端也需要支持你选择的协议、传输方式和 ECH 等参数。

订阅转换可能使用外部转换服务，节点连接参数会交给该服务处理，使用前请确认来源可信。

🚀 优选 IP 和域名

在线优选

在管理面板打开“在线优选 IP”，选择“自定义 IP / 域名”，每行输入一个地址，例如 example.com:443#备注。也支持 IP、CIDR 和地址区间。点击 HTTPS 初筛，再对结果执行 一键测速，勾选需要的结果并点击 导入到优选列表。

导入后还需要在管理面板检查列表、选择自定义订阅模式并保存，然后在客户端更新订阅。在线服务测得的数值反映当时的测试路径，不能直接等同于实际代理连接的速度和稳定性。

Windows 本地优选

下载 CFData 本地优选包，解压并运行 install.cmd。安装后可以从面板的“本地优选IP”入口打开本机页面。完成测速后，将结果手动复制到面板中的自定义优选地址，保存并更新订阅。

项目还提供“本地 Clash 实测”，需要本机运行 mihomo 并配置 external-controller 接口及允许的网页来源。它用于检测节点延迟，与在线下载测速是不同的测试。不要将本机控制接口开放到公网。

❓常见问题

首页显示 404：未设置 URL 时属于预期行为，后台入口是 /admin。

提示没有配置持久化存储：检查生产环境是否配置了原生 KV，或者手动部署所需的账号 ID、加密 Token、存储名称 / ID 是否齐全。补充变量后需要新部署。

保存失败或出现 503：查看错误文字，核对 Token 权限、账号和有效期。不要为了排错删除原 KV，避免丢失配置。

优选结果已导入但订阅没有变化：确认切换到自定义订阅模式、保存设置，并在客户端更新订阅。

收到 CPU 超限通知：Cloudflare 免费套餐对单次 Worker 调用有 CPU 时间限制。检查项目的 Functions Metrics 和日志，区分 CPU 超限、请求数量和其他错误。项目优化可以减少部分开销，实际效果仍取决于请求和使用情况。Cloudflare 限制说明

📌 更新和项目来源

Pages 连接的是自己的 GitHub 仓库。同步代码后，检查 Cloudflare 的新部署是否成功，再在客户端更新订阅。保留原来的 KV 名称或 ID，避免误用新的空存储。
